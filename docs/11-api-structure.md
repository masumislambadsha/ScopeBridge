# 11 — API structure

- Base `/api`; auth via `Authorization: Bearer <access>` (15 min) + first-party `refreshToken` cookie (7 d, rotated, Redis jti).
- Envelopes (§3.2): success `{ success:true, data, meta? }` (lists: `{ data, meta }`; AI queue: `202 { aiRunId }`); errors `{ success:false, error:{ code, message, details? } }`. No 204.
- Codes: VALIDATION_ERROR 400 (incl. all ZodError/multer), UNAUTHENTICATED 401, FORBIDDEN 403, NOT_FOUND 404 (also cross-workspace), CONFLICT 409 (P2002, state transitions), FILE_TOO_LARGE 413, RATE_LIMITED 429 (api/auth/ai limiters), INTERNAL 500 (no internals).
- Every route: auth (except public auth/invite-preview/health/docs) + access resolver + `can()` + `validate()` on body/query/params. All lists paginated (`page`/`limit`, max 100).
- Modules: `backend/src/modules/<domain>/{*.routes,*.controller,*.service,*.schemas}.ts` — thin controllers, state machines in services (unit-testable).
- Auth/session: §3.3 (in-memory token frontend, `/api/*` rewrites, direct uploads/sockets, `GET /me`, refresh-on-load).
- Realtime: JWT handshake, `user:<id>` / `project:<id>:team|client` rooms, access-checked joins, event→query-invalidation map on the frontend.
- Full reference: Swagger UI at `/api-docs`, machine-readable `docs/openapi.json` (generated by `npm run openapi:export`; CI `openapi:check` fails on missing routes).
