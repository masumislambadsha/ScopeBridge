# 01 — Problem statement

Small software agencies lose money to **scope creep**: client requests arrive scattered across WhatsApp, email, calls, PDFs and meetings; nobody can later prove what was agreed; "small changes" accumulate into unpaid weeks of work; and disputes over what was in scope damage client relationships.

Root causes:
1. **No single intake trail.** Client input lives in chat threads, not in the project record.
2. **Requirements are informal.** Nothing links "the client said X" to "we will build Y".
3. **Scope is not versioned.** There is no frozen, client-signed definition of done per phase.
4. **Change has no firewall.** New asks flow straight into development without impact analysis or re-approval.
5. **Approvals are not evidence.** A "yes on WhatsApp" is not a timestamped, hash-verified, signed record.

ScopeBridge exists to make every step traceable and every change gated: intake → requirements → AI analysis → versioned scope → signed approval → tasks → analyzed, human-approved change requests → new versions. See `03-solution.md`.
