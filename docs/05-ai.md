# 05 — AI features

## Provider (`backend/src/services/ai/provider.ts`)
- `AiProvider.generateJSON({ system, user, schema, inlineParts, timeoutMs })`.
- **Gemini** via REST `POST /v1beta/models/{model}:generateContent` with the key in the **`x-goog-api-key` header** (never the URL), `responseMimeType: application/json`, then **Zod validation**. Default model **`gemini-2.5-flash`** (stable Flash endpoint per official docs, Oct 2026; overridable via `GEMINI_MODEL`).
- **Mock**: deterministic fixtures per feature (readiness/acceptance derive real requirement codes from the prompt), plus failure mode (`MOCK_AI_FAIL=1`). Tests always use mock; production refuses mock.
- **Hardening**: client text/files wrapped as DATA with an ignore-instructions guard; inputs truncated/chunk-capped (PDF/image inline parts capped at 4 × 8 MB); AI routes rate-limited separately.

## AiRun lifecycle
Every call creates an `AiRun` (QUEUED → PROCESSING/COMPLETED/FAILED, model, latency, error, output). Endpoints return `202 { aiRunId }`; `GET /api/ai/runs/:id` reports status; completion/failure emits `ai:run:updated`. BullMQ retries (3× exponential); final failure → FAILED + PM notification + manual-mode banner + Retry button. **AI never writes APPROVED/REJECTED** (asserted by `tests/ai-failure.test.ts` source scan + behavior tests).

## The five
- **AI-01 checklist** — sync (25 s timeout), `{ sections[] }` + `source: AI|TEMPLATE`; per-`ProjectType` templates (E_COMMERCE covers business/product/branding/payments/delivery/refunds); UI turns picks into IR questions.
- **AI-02 extraction** — auto on submission + manual 202; Q→A pairs + additional info + extracted file text + PDF/image inline parts; `sourceExcerpt` verified by normalized substring (confidence lowered + flagged if absent); DRAFT + `REQ-xxx` + sourceContext; duplicates flagged; then auto-queues AI-03.
- **AI-03 readiness** — all non-REJECTED requirements **by code**; `{ readinessScore, summary, missingInformation, ambiguous, contradictions, incomplete, unclear, perRequirement }`; stored as `ReadinessReport` + per-requirement `aiFlags`; PM applies Mark ready / Request clarification (bulk).
- **AI-04 criteria** — by `requirementIds[]` or `scopeVersionId`; 2–6 Given/When/Then each; saved AI_DRAFT on requirements + draft features; REVIEWED never overwritten without `replace=true`.
- **AI-05 change analysis** — CR (+files) vs **base approved version** (features/criteria/deliverables/**exclusions** — exclusion matches force OUT_OF_SCOPE); `{ classification, confidence, matchedScopeItems, impact{work/db/api/ui/timeline/effort}, rationale, suggestedRequirements }`; PM `finalClassification` is final.
